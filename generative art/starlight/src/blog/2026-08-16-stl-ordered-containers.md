[新手入门 130 题](https://www.nowcoder.com/problem/tracker#/problems)的集合与优先队列文件夹，表面是 STL 语法题，实际藏着几个**比赛里真实会踩的坑**。这篇当避坑笔记写。

## 一、multiset 的 erase 陷阱

> **题意**（【模板】多重集合操作）：multiset 支持插入/删除/查询，删除只删**一个**。

STL 最著名的坑之一：

```cpp
ms.erase(x);         // 把所有等于 x 的元素全删光！
ms.erase(ms.find(x)); // 只删一个 —— 正确写法
```

配套记忆：`count(x)` 在 multiset 上是 O(计数) 而非 O(1)（set 上 `size()` 与 `count` 也可能线性），高频调用时用 `find != end()` 判存在就够了。

## 二、动态集合取最近值（二分边界训练）

> **题意**（动态整数集最近值提取）：支持插入（重复报错）和"取出与 x 最接近的元素"，距离相等取较小者。

`lower_bound` 找到后继 a，回退一个得前驱 b，比较 `x - b` 与 `a - x`；两端特判（x 比最小还小/比最大还大）。这是 set 二分的标准操练：**后继是 lower_bound，前驱是它前面那个**，两个候选一比即出。

## 三、快乐数：判环的三种姿势

> **题意**（快乐数，LeetCode 202 同款）：反复把 n 替换为数位平方和，问最终能否到 1。

到不了 1 的数会**陷入同一个环**（4 → 16 → 37 → … → 4），于是判环即可，三种写法：

```cpp
// 1) 哈希/multiset 记录出现过的数，重复即环
// 2) 快慢指针：slow 走一步、fast 走两步，相遇即环（O(1) 空间）
// 3) 数学：n > 9 时一直变换，最后判 n == 1（环只含 4 的结论）
```

链表判环、迭代函数收敛判环、随机数周期——同一模型在到处复用。

## 四、A−B=C 的数对计数

> **题意**（数对计数）：统计序列中满足 A − B = C 的有序对个数。

multiset 版：对每个元素查 `count(x + C)`，迭代器逐个前进保证重复元素各自被数到。升级写法是排序 + 双指针或哈希表 O(n)——同一道题把"有序容器计数"和"哈希计数"对照着写一遍，边界感觉会好很多。

## 五、堆贪心：每次给最小值 +b

> **题意**（小苯的比赛上分类）：n 个初始值，m 次操作每次给**当前最小值** +b，输出每次操作后的最大值。

小根堆每次弹最小、加 b、回堆；最大值**单独维护**一个只增不减的变量（每 +b 后与历史最大比较）：

```cpp
for (int i = 0; i < m; i++) {
    long long v = pq.top(); pq.pop();
    v += b; pq.push(v);
    maxx = max(maxx, v);   // 最大值单调，无需进堆
}
```

**核心**：堆只维护"谁是最小"，答案另账记录——**数据结构不必包办一切**，能单调维护的量就别查询。同文件夹的"双端优先队列"（查最大删最大 + 查最小删最小）是它的加强版，multiset 或对顶堆都能做。

## 小结

| 场景 | 一句话 |
|---|---|
| multiset 删一个 | `erase(find(x))`，别 `erase(x)` |
| 最近值 | lower_bound 后继 + 前驱比较 |
| 迭代判环 | 哈希 / 快慢指针 / 数学，三选一 |
| 差值数对 | 有序计数或哈希，双指针更稳 |
| 堆贪心 | 堆管最小，最大另账单调维护 |
