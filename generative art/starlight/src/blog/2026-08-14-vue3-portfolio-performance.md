你正在浏览的这个网站：Vue 3 + TypeScript + Vite + Tailwind CSS 4 + Three.js + GSAP，GitHub Actions 自动部署到 GitHub Pages。这篇文章复盘它的开发过程与性能设计。

## 先写计划，再写代码

动工前先调研了 5 个同类开源项目，产出一份设计文档：页面结构、动画规格、性能预算、部署方案全部先定死，再拆成 21 个任务逐个实现、逐个提交、逐个审查。

几条从调研里学到的核心纪律：

- **滚动与 3D 解耦**：GSAP 只 tween 普通数据对象，渲染循环每帧读取——参考了 Codrops 电影级滚动项目的做法；
- **GPU 粒子**：粒子的运动属性（半径/速度/漂移）全部进 BufferAttribute，运动在 vertex shader 里算，CPU 每帧只更新一个 uniform；
- **成对 init/destroy**：Three.js 场景与 GSAP 动画都必须有明确的销毁路径，SPA 路由切换不泄漏。

## 三个真实的坑

**坑一：类型检查根本没生效。** 最初构建脚本用 `vue-tsc --noEmit`，根 tsconfig 只引用了 node 工程。实测：在 src 里故意写一个类型错误，构建依然通过——src 从未被类型检查。修复：根 tsconfig 引用 app + node 两个工程、改用 `vue-tsc -b`，并用"注入错误必须失败"的双探针验证。

**坑二：冻结星空。** 粒子密度按路由分档（首页密/内容页稀/文章页关）。验收时发现：切到文章页后 canvas 停止渲染，却残留最后一帧——一整片静止星空。修复只有一行：密度归零时 `renderer.clear()`。

**坑三：测试全绿，页面却空白。** 博客页在浏览器里一片空白：`gray-matter` 依赖 Node 的 Buffer，浏览器没有这个全局对象，组件初始化直接抛错；而单元测试跑在 Node 环境，全部通过。**测试环境与浏览器环境的差异，只能靠真实浏览器验收发现。** 最后换成浏览器安全的 js-yaml，并补了一个 jsdom 环境的回归测试。

## 性能清单（预算内实现的）

- 粒子 ≤ 1000 且全 GPU 渲染；移动端（<768px）直接关闭；
- DPR 封顶 2；页面不可见时暂停渲染循环；尊重 prefers-reduced-motion；
- 首屏 JS < 300KB：markdown-it + shiki 只在博客详情页懒加载（博客分包最终 47KB）；
- 所有动画只动 transform/opacity，不触发布局。

## 实测数字

性能预算不是写在文档里就完事的，每个数字都要实测兑现：

- **帧率**：粒子页 rAF 回调 164 次/秒（高刷屏下无掉帧），移动端粒子直接关闭；
- **内存**：路由来回切换 10 次，堆内存 29MB → 31MB，无累积泄漏；
- **体积**：首屏 JS gzip 约 145KB（预算 300KB 内），博客渲染依赖全部在懒加载分包里；
- **验收方式**：每个阶段结束用浏览器自动化截图，交给视觉模型描述页面——三个阶段下来抓到了"冻结星空""博客页空白"这类代码审查发现不了的问题。

## 验收方法论

每个阶段结束，用浏览器自动化截图，再交给视觉模型描述页面——"博客页仍有星空"这类问题，代码审查发现不了，截图一眼就能看出。这个流程比人工点页面更快，也比只跑测试更接近真实用户。
